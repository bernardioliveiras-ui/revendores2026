LORD NUTRI — PLATAFORMA E AUTOMACOES (21/11/2026)

Este ZIP contem o projeto completo para atualizar o codigo no GitHub.
Nao contem node_modules, build .next, arquivos .env, credenciais ou exportacoes CSV.
Antes de sobrescrever os arquivos locais, faca uma copia do seu projeto atual.
O ZIP nao e um backup do banco MariaDB: preserve o banco separadamente.

O QUE FOI CORRIGIDO
- Editar o nome da campanha no portal do influenciador ou BKO muda o link de
  vendas no mesmo salvamento: /v/nome-da-campanha (sem codigo hexadecimal).
- Quando ja existir uma campanha com o mesmo nome, o sistema usa um sufixo
  numerico para manter URLs unicas (ex.: /v/promo-2).
- O identificador interno de atribuicao de vendas NAO muda ao renomear.
- Links antigos deixam de ser a referencia apos renomear. Este e o comportamento
  solicitado para uma plataforma ainda em implantacao, sem links divulgados.
- Expedicao BKO: busca, indicadores, tabela, detalhes e ultimo evento consultado.
- Nova acao "Sincronizar Correios agora" restrita ao BKO.
- Consultas validas sem evento e falhas dos Correios ficam diferenciadas:
  "Ultima consulta valida" e "Ultima tentativa"; eventos anteriores preservados.
- BKO e revendedor atualizam as telas de operacao a cada 30 segundos quando
  o navegador estiver visivel. Os Correios sao consultados PELO SERVIDOR, nao
  pelo navegador do cliente.
- Workflow GitHub Actions agenda consultas a cada 10 minutos, SE devidamente
  configurado e efetivamente executado pela plataforma GitHub.
- BKO separa compras por canal sem mover dados do banco:
  * Acessos e Pedidos: apenas KIT20, KIT50 e KIT100 de revenda.
  * Influenciadores: compras unitarias com campanha e cashback atribuido.
  * Vendas avulsas: MIX10 unitario sem campanha; nao gera acesso de revendedor.
  * Expedicao: todos os pedidos pagos, por ser uma operacao compartilhada.
- O contador "Acessos pendentes" considera SOMENTE kits pagos e verificados
  no Asaas. Compras unitarias nao criam pendencia de acesso.
- Visao Geral distingue totais da loja inteira dos canais de kits,
  campanhas e vendas avulsas. Compras recentes mostram sua origem.
- CSS do projeto esta incluido em app/portal-modern.css; a equivalencia
  visual com cada tela da demo ainda exige conferencia no BKO autenticado.

ATIVACAO DO RASTREIO REAL — OBRIGATORIA
1. No painel da Hostinger, configure como variaveis privadas:
   CORREIOS_USUARIO, CORREIOS_CODIGO_ACESSO, CORREIOS_CONTRATO e
   CORREIOS_CRON_TOKEN (segredo forte de pelo menos 32 caracteres).
2. No GitHub do repositorio, Settings > Secrets and variables > Actions:
   - Secrets: CORREIOS_CRON_TOKEN (MESMO valor configurado na Hostinger).
   - Variables: PORTAL_URL=https://revendedores.mix10pro.com.br
3. Confirme que Actions esta habilitado, que a branch principal contem
   .github/workflows/correios.yml e que a rotina foi executada com sucesso.
   O agendamento do GitHub pode atrasar. Nao e rastreamento instantaneo.
4. Para cada pedido pago, cadastre etiqueta valida (ex.: AA123456789BR)
   e use transportadora Correios. Sem etiqueta ou sem credenciais oficiais,
   o sistema nao tem como consultar o objeto real.
5. No BKO > Integracoes confira o diagnostico e em Expedicao clique em
   "Sincronizar Correios agora" para a primeira verificacao.
6. Abra o pedido no portal do revendedor e confira o evento, a etapa e
   os horarios. A ausencia de eventos ainda depende da resposta dos Correios.

ANTES DO DEPLOY
- Faca backup do codigo e banco. Nao apague ou 'zere' dados para aplicar esta
  atualizacao. Revise migracoes pendentes em ambiente isolado primeiro.
- Nunca publique DATABASE_PASSWORD, ASAAS_API_KEY, segredos Correios ou .env.
- Confira a configuracao do banco da aplicacao na Hostinger; um build aprovado
  nao comprova que o banco real esta acessivel.
- Rode localmente: node --test tests/*.test.mjs ; npm run build.
- Extraia os ARQUIVOS do ZIP na pasta do projeto git local (nao envie apenas
  o arquivo .zip ao GitHub). Revise as alteracoes no GitHub Desktop e faca push.
- Espere o deploy e teste as tres contas separadas: BKO, Revendedor,
  Influenciador. Inspecione os logs e respostas da plataforma.
